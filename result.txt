2. Vite base-path changes
vite-plugin-singlefile (v2.3.0) forces config.base = "./" from its own config hook, so a normal top-level base in defineConfig is silently overridden. I verified this with Vite's resolveConfig (a top-level base resolved back to "./"). I therefore set the base through the plugin's supported overrideConfig escape hatch, only for builds:
viteSingleFile(command === "build" ? { overrideConfig: { base: PAGES_BASE } } : {})
Verified resolved values:
- command=build → base="/hand-tracking-galaxy/" ✅
- command=serve (dev) → base="/" (unchanged localhost behavior) ✅
Because the single-file plugin inlines all JS/CSS (and there is no public/ dir), the production dist/index.html is fully self-contained — no /assets/ or local asset URLs — so it works at the Pages subpath. The single-file plugin and all app behavior were preserved.
